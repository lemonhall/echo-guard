# 📋 EchoGuard 依赖升级建议书：webrtc-audio-processing v0.3 → v2.1

## 发起人：柠檬叔
## 日期：2026-02-08
## 优先级：高（当前 AEC 效果差的根本原因）

---

## 一、问题定性

当前项目的回声消除效果差，**根因不是我们的代码写得有问题，而是依赖的底层库太老了**。

### 当前依赖

```
submodule: deps/webrtc-audio-processing
来源: https://github.com/cross-platform/webrtc-audio-processing
版本: v0.3.1（基于 ~2016 年的 WebRTC 代码）
最后实质提交: 2018 年
AEC 算法: AEC2（旧版，需要手动传延迟，延迟不准就废了）
状态: 事实上已死，原作者 3 年没动了
```

### 应该用的

```
来源: https://gitlab.freedesktop.org/pulseaudio/webrtc-audio-processing
版本: v2.1（2025-01-23 发布，基于 Chromium M131 的 WebRTC 代码）
AEC 算法: AEC3（自带动态延迟估计，不需要手动传延迟）
状态: 官方维护，活跃
```

### 版本差距可视化

```
官方版本线:
  v0.3 → v1.0 → v1.1 → v1.2 → v1.3 → v2.0 → v2.1
   ↑       ↑                                     ↑
 我们在这  AEC3 从这里开始成为默认              当前最新
 (2016)   (2021)                              (2025-01)
```

**我们落后了 6 个大版本，跨越了 9 年的 WebRTC 音频处理算法迭代。**

---

## 二、升级目标

将 `deps/webrtc-audio-processing` 从 GitHub `cross-platform` 的 v0.3 fork 切换到 **freedesktop.org 官方的 v2.1**，并适配 C++ 插件代码使用 AEC3 新 API。

---

## 三、升级步骤

### 步骤 1：移除旧 submodule，引入新依赖

```powershell
# 在项目根目录（godot/native/echo_guard 或对应位置）
git submodule deinit deps/webrtc-audio-processing
git rm deps/webrtc-audio-processing
rm -rf .git/modules/deps/webrtc-audio-processing   # 清理残留

# 引入官方 v2.1
git submodule add https://gitlab.freedesktop.org/pulseaudio/webrtc-audio-processing.git deps/webrtc-audio-processing
cd deps/webrtc-audio-processing
git checkout v2.1
cd ../..
git add .gitmodules deps/webrtc-audio-processing
git commit -m "deps: switch webrtc-audio-processing to official v2.1 (AEC3)"
```

### 步骤 2：处理新增依赖 abseil-cpp

v2.0+ 新增了对 `abseil-cpp 20240722` 的依赖。官方 meson 构建会自动通过 subproject 拉取，但如果我们的构建系统是 CMake/SCons，需要注意：

- **如果用 meson 构建 deps**：不需要额外操作，meson 会自动处理
- **如果用 CMake/SCons 构建 deps**：需要手动引入 abseil-cpp，或者先用 meson 把 deps 编译成静态库再链接

> ⚠️ 请先检查当前项目的构建系统（CMakeLists.txt / SConstruct / meson.build），确认 deps 是怎么被编译和链接的，再决定 abseil-cpp 的引入方式。

### 步骤 3：适配 C++ 插件代码（核心改动）

改动文件：`godot/native/echo_guard/src/echo_guard_processor.cpp` 和对应 `.h`

#### 3.1 头文件变更

```cpp
// 旧（v0.3）
#include "webrtc/modules/audio_processing/include/audio_processing.h"

// 新（v2.1）—— 路径可能变化，需要确认实际安装路径
#include "webrtc/modules/audio_processing/include/audio_processing.h"
// 或者
#include "api/audio/audio_processing.h"
```

> ⚠️ v2.1 的头文件目录结构可能与 v0.3 不同，请以实际源码树为准。

#### 3.2 APM 创建方式变更

```cpp
// ========== 旧代码（v0.3 / AEC2）==========
webrtc::AudioProcessing* apm = webrtc::AudioProcessing::Create();

// 启用 AEC
apm->echo_cancellation()->Enable(true);
apm->echo_cancellation()->set_suppression_level(
    webrtc::EchoCancellation::kHighSuppression);
apm->echo_cancellation()->enable_drift_compensation(false);

// 启用其他模块
apm->noise_suppression()->Enable(true);
apm->noise_suppression()->set_level(webrtc::NoiseSuppression::kHigh);
apm->gain_control()->Enable(true);
apm->high_pass_filter()->Enable(true);

// 可选的 extra options
webrtc::Config config;
config.Set<webrtc::ExtendedFilter>(new webrtc::ExtendedFilter(extended_filter));
config.Set<webrtc::DelayAgnostic>(new webrtc::DelayAgnostic(delay_agnostic));
apm->SetExtraOptions(config);


// ========== 新代码（v2.1 / AEC3）==========
webrtc::AudioProcessing::Config config;

// AEC3 —— 就这么简单，不需要设延迟！
config.echo_canceller.enabled = true;
// config.echo_canceller.mobile_mode = false;  // 桌面端用 false

// 降噪
config.noise_suppression.enabled = true;
config.noise_suppression.level = webrtc::AudioProcessing::Config::NoiseSuppression::kHigh;

// 增益控制
config.gain_controller1.enabled = true;
// 或者用新的 gain_controller2
// config.gain_controller2.enabled = true;

// 高通滤波
config.high_pass_filter.enabled = true;

// 创建 APM 实例
auto apm = webrtc::AudioProcessingBuilder()
    .SetConfig(config)
    .Create();
```

#### 3.3 处理循环变更

```cpp
// ========== 旧代码 ==========
// 每帧都要手动设延迟（这就是效果差的直接原因！）
apm->set_stream_delay_ms(delay_ms);          // ← 删掉这行！
apm->ProcessReverseStream(ref_frame);         // 喂参考信号
apm->ProcessStream(mic_frame);                // 处理麦克风信号


// ========== 新代码 ==========
// 不需要 set_stream_delay_ms()！AEC3 内部自己估延迟！
apm->ProcessReverseStream(ref_frame);         // 喂参考信号
apm->ProcessStream(mic_frame);                // 处理麦克风信号
// 就这样，完事了
```

#### 3.4 StreamConfig 变更

```cpp
// StreamConfig 的构造方式基本不变，但请确认：
webrtc::StreamConfig config(sample_rate, num_channels);
// v2.1 中 StreamConfig 的 API 应该是兼容的，但需要验证
```

#### 3.5 需要删除的代码

以下旧 API 在 v2.1 中 **已不存在**，必须删除：

```cpp
// 全部删掉：
apm->echo_cancellation()          // 整个对象不存在了
apm->noise_suppression()          // 改用 Config 方式
apm->gain_control()               // 改用 Config 方式
apm->high_pass_filter()           // 改用 Config 方式
apm->set_stream_delay_ms()        // AEC3 不需要
apm->SetExtraOptions()            // 不存在了
webrtc::ExtendedFilter            // 不存在了
webrtc::DelayAgnostic             // 不存在了
```

### 步骤 4：GDScript 侧清理

以下 GDScript 接口可以 **简化或删除**：

```
set_aec_delay_agnostic(bool)   → 删除（AEC3 天然 delay-agnostic）
set_aec_extended_filter(bool)  → 删除（AEC3 不需要）
set_stream_delay_ms(int)       → 删除（AEC3 自己估延迟）
```

可以新增：

```
set_aec_mobile_mode(bool)      → 对应 config.echo_canceller.mobile_mode
```

## 四、风险点和注意事项

| 风险 | 说明 | 应对 |
|------|------|------|
| **abseil-cpp 依赖** | v2.0+ 必须链接 abseil-cpp，这是个不小的 C++ 库 | 先确认构建系统怎么引入；meson 构建最省事 |
| **头文件路径变化** | v2.1 的源码目录结构可能与 v0.3 不同 | 编译时根据报错调整 include path |
| **Windows 构建** | v2.1 的 NEWS 提到专门修了 Windows 构建问题 | 应该比 v0.3 更好，但需要实测 |
| **API 完全不兼容** | 不是小改，是整个 API 风格都变了（从运行时配置变成构建时配置） | 上面步骤 3 已经列出了完整的迁移对照 |
| **TransientSuppression 被移除** | 如果用了这个功能，v2.0+ 没有了 | 检查当前代码是否用到，大概率没用 |

## 五、预期收益

```
升级前（AEC2 / v0.3）：
  ❌ 手动传延迟 30ms，不准就废
  ❌ 自适应滤波器短（~60ms）
  ❌ 2016 年的算法，对非线性回声处理差
  ❌ 依赖库已死，无人维护

升级后（AEC3 / v2.1）：
  ✅ 自动延迟估计，不需要手动传
  ✅ 自适应滤波器更长，收敛更快
  ✅ Chromium M131 的算法，经过数十亿设备验证
  ✅ 官方维护，有 bug 可以报
  ✅ C++ 插件代码反而更简单（删掉一堆手动配置）
```
